# Contributing

1. Fork the repo and create a branch: `git checkout -b feat/short-description`
2. Make your changes. Keep pull requests small and focused.
3. Make sure both apps still run: `npm run build` in `client`, `npm run dev` in `server`.
4. Use clear commit messages, for example `feat: add DOCX upload` or `fix: handle empty PDF`.
5. Open a pull request describing what changed and why.

Never commit `.env` files or API keys.
